# ai-rules

Central, versioned repository of AI-agent rules for my projects, inspired by the
`storytold/artcraft-services` model (hierarchical `AGENTS.md` + `CLAUDE.md` pointer),
generalized for the stack: **Node.js · Fastify · React · Vite · Tailwind · Zustand · Prisma/Supabase**.

## How it works

`rules/` contains numbered rule **fragments** (single source of truth per topic).
`sync.sh` detects a target project's stack and **composes** the right fragments into
`AGENTS.md` files inside that project. Projects only carry the generated output —
they never reference this repo by path.

```text
rules/
├── 00-header.md          # GENERATED banner + AGENTS.local.md note
├── 10-overview.md        # per-project overview skeleton ({{PROJECT_NAME}})
├── 20-code-style-js.md   # universal JS/React style
├── 30-backend-fastify.md # Fastify conventions        → backend/api/ scope
├── 35-db-prisma.md       # applied when prisma detected → backend/api/ scope
├── 36-db-supabase.md     # applied when supabase detected → backend/api/ scope
├── 40-frontend-react.md  # React/Vite/Tailwind/Zustand → frontend/ scope
├── 50-testing.md         # vitest + node:test for new code
├── 60-git-hygiene.md     # one package manager, .gitignore rules
├── 70-docs-policy.md     # no status/summary .md sprawl
├── 80-security-env.md    # env vars, secrets, CORS, webhooks
├── 90-deploy-vercel.md   # applied when vercel.json exists
├── python-stub/AGENTS.md # standalone template for Python projects
└── stubs/CLAUDE.md       # pointer file (fallback when symlinks unavailable)
```

## Usage

```bash
# Preview what would be generated for one project (writes nothing):
./sync.sh --check /path/to/project

# Sync one project:
./sync.sh /path/to/project

# Sync every project listed in MANIFEST.txt:
./sync.sh --all

# Force the stack when detection is ambiguous:
./sync.sh --stack fastify,prisma,vercel /path/to/project
```

### What sync writes in the target project

| File                          | Contents                                                    |
|-------------------------------|-------------------------------------------------------------|
| `AGENTS.md`                   | Composed rules for the detected stack                       |
| `CLAUDE.md`                   | Symlink to `AGENTS.md`, or a pointer stub on Windows        |
| `backend/` or `api/AGENTS.md` | Backend + detected DB fragments (if dir exists)             |
| `frontend/AGENTS.md`          | Frontend fragment (if dir exists)                           |
| `AGENTS.local.md`             | Optional, hand-written per project — **never overwritten**   |

Each generated file starts with a `GENERATED by ai-rules vX.Y.Z` banner. Hand-edited
AGENTS.md files without the banner are backed up to `.bak` before being replaced.

## Updating rules

1. Edit a fragment in `rules/` (or add a new `NN-name.md` — update `sync.sh`'s
   fragment table).
2. Bump `VERSION` and note the change in `CHANGELOG.md`.
3. `./sync.sh --all` to roll it out.

## Detection rules

| Signal in project                              | Fragments applied             |
|------------------------------------------------|-------------------------------|
| `fastify` in `package.json` deps               | 30-backend-fastify            |
| `@prisma/client` dep or `prisma/` dir          | 35-db-prisma                  |
| `@supabase/supabase-js` dep                    | 36-db-supabase                |
| `vite.config.*` or `react`/`vite` deps         | 40-frontend-react             |
| `vercel.json`                                  | 90-deploy-vercel              |
| `requirements.txt`/`*.py`, no `package.json`   | python-stub (copied as-is)    |
| `backend/`, `api/`, `frontend/` dirs           | scoped AGENTS.md per dir      |
